## Обзор {#overview}

Разделение расходует один конфиденциальный фрагмент актива и подготавливает два или более выходов. Каждый выход сохраняет исходные `definition_id` и базовый `serial_id`, а сумма всех положительных выходов должна точно совпадать с суммой входа. Операция меняет структуру выходов, но не определение актива и не создаёт дополнительную эмиссию.

Каждый полученный фрагмент приобретает собственную идентичность конкретного выхода, оставаясь частью той же серии выпуска.

## Как использовать этот экран {#how-to-use-this-view}

1. Проверьте активный кошелёк и сеть в заголовке приложения.
2. Выберите **Разделить**.
3. Выберите один доступный исходный фрагмент.
4. Введите от двух до восьми положительных сумм выходов.
5. Убедитесь, что для **Сохранения суммы** указано **Точно**.
6. Выберите **Предпросмотр разделения** и проверьте исходный фрагмент и каждый предлагаемый выход.
7. Продолжайте только в нативном кошельке, который может повторно проверить авторизацию, комиссии, отправку и сверку результата.

## Термины и элементы управления {#terms-and-controls}

| Термин или элемент | Объяснение |
| --- | --- |
| Исходный актив | Единственный доступный фрагмент, расходуемый предлагаемым разделением. |
| ID определения | Неизменяемый идентификатор типа актива и его политики. Каждый выход сохраняет исходное определение. |
| Серийный ID | Базовая серия выпуска. Каждый выход сохраняет серию исходного фрагмента. |
| Распределение выходов | От двух до восьми положительных сумм, назначенных предлагаемым выходам. |
| Сохранение суммы | Точное равенство суммы входа и суммы всех выходов. |
| Добавить выход | Добавляет ещё одно поле положительной суммы до ограничения интерфейса. |
| Предпросмотр разделения | Намерение только для проверки, показывающее источник и предлагаемые выходы; оно ничего не подписывает и не отправляет. |

## Безопасность и ограничения {#safety-and-limits}

- Разделение никогда не меняет исходное определение или базовую серию.
- Нулевые, отрицательные, чрезмерные распределения или распределения без сохранения суммы должны отклоняться.
- Нативный кошелёк должен отклонить источник, который стал заблокированным, потраченным, замороженным, сожжённым, оштрафованным или иначе недоступным.
- Повторяющиеся или необычно шаблонные распределения могут упростить сопоставление связанных выходов.
- JavaScript Demo использует публичные тестовые данные и останавливается на предпросмотре. Оно не хранит ключи, не доказывает владение, не создаёт подписи, не списывает комиссии, не отправляет пакет и не сверяет неопределённый результат.
- Текущий помощник `wallet.asset.split_asset` является поверхностью совместимости и не заявляет канонические полномочия сверки реестра. Нативная интеграция должна направлять подтверждение через авторитетный путь транзакции кошелька.
