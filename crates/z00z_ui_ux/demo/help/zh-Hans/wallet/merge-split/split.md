# 钱包：拆分

[TOC]

## 应用视图 {#current-view}

![钱包拆分视图](help/assets/en/wallet-split.png)

此图像来自当前 Demo 的拆分视图。

## 概览 {#overview}

拆分会消耗一个机密资产片段并准备两个或更多输出。每个输出都保留来源的 `definition_id` 和基础 `serial_id`，所有正数输出金额之和必须与输入金额完全相等。拆分只改变输出的组织方式，不会更改资产定义或创建新的供应量。

每个生成的片段都会获得自己的具体输出身份，同时仍属于同一发行系列。

## 如何使用此视图 {#how-to-use-this-view}

1. 在应用标题栏中确认当前钱包和网络。
2. 选择 **拆分**。
3. 选择一个可用的来源片段。
4. 输入两个到八个正数输出金额。
5. 确认 **守恒** 显示为 **精确**。
6. 选择 **预览拆分**，检查来源和每个拟议输出。
7. 仅在能够重新检查授权、费用、提交和对账的原生钱包中继续。

## 术语和控件 {#terms-and-controls}

| 术语或控件 | 说明 |
| --- | --- |
| 来源资产 | 拟议拆分所消耗的唯一可用片段。 |
| 定义 ID | 资产类型及其策略的不可变标识符。每个输出都保留来源定义。 |
| 系列 ID | 基础发行系列。每个输出都保留来源系列。 |
| 输出分配 | 分配给拟议输出的两个到八个正数金额。 |
| 守恒 | 输入金额与所有输出金额之和完全相等。 |
| 添加输出 | 在界面限制内添加另一个正数分配字段。 |
| 预览拆分 | 仅供检查的意图，显示来源和拟议输出；不会签名或提交。 |

## 安全性和限制 {#safety-and-limits}

- 拆分不会更改来源定义或基础系列。
- 零值、负值、过大或不满足金额守恒的分配必须被拒绝。
- 原生钱包必须拒绝后来变为已锁定、已花费、已冻结、已销毁、已罚没或以其他方式不可用的来源。
- 重复或具有异常模式的分配可能使相关输出更容易被关联。
- JavaScript Demo 使用公开测试数据，并在预览阶段停止。它不持有密钥、不证明所有权、不创建签名、不收取费用、不提交数据包，也不对不确定结果进行对账。
- 当前 `wallet.asset.split_asset` helper 是兼容性接口，不声明拥有规范账本对账权限。原生集成必须通过权威的钱包交易路径进行确认。
